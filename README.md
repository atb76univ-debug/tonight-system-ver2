# tonight!（イベント運営アプリ）

受付・バーカウンター・メンバー名簿・出演／シフト・タイムテーブルを管理するクラウド同期アプリです。

## v40 更新方針

v32を画面遷移の基準として再構成し、v33以降で追加された必要な機能だけを選んで移植しました。

- ニックネーム（DJネーム）を名簿に登録・編集・インポート可能。ニックネームがある場合は優先表示し、ない場合は本名を表示。
- 出演・シフトのメンバー選択、NOW/NEXT、タイムライン、受付メンバー表示でニックネームを利用。
- `memberDisplayName` と `recordMemberDisplay` をトップレベル関数として定義し、タイムテーブル描画処理から確実に参照できるように整理。
- 学年・ニックネームを含むCSV／Excelインポート。Excelは先頭30行から見出し行を検出し、既存メンバーは名前で照合。学年の空欄で既存データを消さない。
- メンバー名簿の全員選択・選択者一括削除。参加予定リストからも除外し、過去の履歴は保持。
- 不完全な旧タイムテーブルデータの `acts`・`shifts` を補完する `ensureTt` を維持。
- 戻るボタンと `navigate` / `back` の実装はv32のものを維持し、v33以降で変更された画面遷移処理を持ち込まない。
- Cloudflare Worker名は `tonight-system` を維持。Durable Object `STORE` とAssets設定も維持。
- Wranglerは `4.157.0` に固定。

## デプロイ

リポジトリのルートに `public/` と `src/` を置き、Cloudflareで次のコマンドを実行します。

```bash
npm install
npm run deploy
```

Worker名・Durable Objectバインディング・Assets設定を変更しないでください。

## 不具合修正（2026-11-04 / 検証後）
- **受付履歴の復元が元に戻る問題**：回全体（`state`）を「更新時刻が新しい方」で丸ごと上書きしていたため、時計の進んだ端末や古いデータを持つ端末が後から保存すると復元が消えていました。受付履歴を1件ごとに「削除／復元の新しい方」で統合する処理（`mergeReceptionStates`）を `app.js` と `worker.js` の両方に追加し、来場者数・金額・ドリチケ残数も統合結果に合わせて自動補正します。削除・復元の時刻は、端末の時計がずれていても必ず前回操作より後になるようにしました。
- **復元後に受付タブが消える問題**：削除・復元・一括削除の後に画面だけを再描画していたため、タブが失われていました。タブとヘッダーも含めて再描画する `refreshCurrentView` に統一。
- **バーカウンター現金会計の手順**：受付と同じ「預かり金額 →（確認へ）→ 会計確認（チェックボックス）→ 会計を確定」の2ステップに統一。確認画面から金額入力に戻ることも可能。
- **iPad／タブレット表示**：ステータスバー・ノッチの安全領域、NOW/NEXTバーとヘッダーの重なり防止、タッチ端末でのホバー固着防止、入力欄のiOS自動ズーム防止、タップ領域の拡大、iPad向けの文字・商品タイル・タブサイズ、横向きでの預かり金額ダイアログ2列化、ダイアログ上端が切れる問題の解消。
- キャッシュ更新のため `sw.js` を `tonight-v22` に、`index.html` の読み込みバージョンを更新。

## イベントごとの料金設定
- イベントホームの「料金設定（この回）」から、エントランス代・1stドリンクチケット代・箱代・割引額（2種類）を変更できます。
- 新規イベントの初期値は従来どおり、エントランス1,000円／1stドリンク500円／箱代10,000円／割引500円・1,000円です。
- 設定はイベントごとに保存され、受付会計・割引選択・精算・利益計算・CSV出力に反映されます。
- 既存イベントに料金設定がない場合は従来の金額を初期値として補完します。


## 料金設定の参照漏れ修正（2026-11-04）
- リザルト画面の箱代表示・精算後金庫額の差し引き表示を、イベントごとの料金設定に統一。
- 割引人数の内訳を固定の500円／1,000円表示から、実際に適用された割引額ごとの動的表示に変更。
- 金庫照合の理論金庫額・差額計算もイベントごとのドリンクチケット代・箱代を参照。
- 過去データで受付総額が未保存の場合の補完値は、当時の標準料金を使用し、後からイベント料金を変更しても過去の履歴を誤計算しないように整理。


## タイムテーブル／シフトのページ分離
- イベントホームから「タイムテーブル」と「シフト」を別々に開けます。
- タイムテーブルページには出番の一覧・追加編集・出番タイムラインを表示します。
- シフトページにはシフトの一覧・追加編集・シフト専用タイムラインを表示します。
- 両ページのヘッダーに相互移動ボタンを設置しました。
- 既存の `tt.acts` / `tt.shifts` データ構造は維持しているため、保存済みデータの移行は不要です。
